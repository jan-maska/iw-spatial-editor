Start

Open it and begin.

The Visual Editor is one self-contained HTML application. Use the hosted version, or open dist/index.html from the downloaded package in a modern browser. No installation, local server, account, or network connection is required.

The initial view contains a small Eldren demonstration world. Choose New for an empty project, Open project for an existing .iwspatial file, or Import YAML to begin from Spatial Context source files.

Compatibility: Editor 0.4.0 targets IW Spatial Context 1.0 RC3 and schema 1.2.

Authoring workflow

From reference map to source files.

  1. Optionally load a background image and calibrate its X/Y bounds in the Project inspector.
  2. Draw locations, paths, and polygonal area geometries. Drag points or vertices to reposition them.
  3. Classify objects with the shared Type and Subtype controls. Built-in values use consistent map colors; custom values remain available.
  4. Marquee-select mixed geometry. Use Shift to add or Ctrl/Alt to remove, then drag any selected object to move the complete group.
  5. Double-click path segments or polygon boundaries to add vertices. Reverse ordered paths with Flip direction.
  6. Save the complete working project as .iwspatial.
  7. Run Validate, then export world-geography.yaml and world-spatial.yaml.

Marquee and group movement

Drag across empty map space to select every intersecting location, path, and polygon. Shift-marquee adds to the selection; Ctrl/Alt-marquee removes. Drag any selected object to move the complete selection without changing relative positions.

Vertex editing

Select one path or polygon to expose its vertices. Drag a vertex to move only that point. Double-click a segment or boundary—or choose Insert midpoint in the inspector—to add a vertex exactly where it is needed.

Precision and snapping

One-metre view, ten-metre authoring.

X/Y coordinates are kilometres; elevation is metres. The viewport uses a logarithmic scale from 0.001 to 1 km/px. At maximum zoom, one screen pixel represents one metre.

Snap points to 10 m grid is enabled by default. It matches Spatial Context's normal 0.01 km horizontal resolution and applies consistently to:

  • new locations, paths, and polygon points;
  • vertex insertion and individual dragging;
  • group movement and linked intersections;
  • inspector coordinate edits;
  • initial-navigation X/Y values.

Disable snapping only when imported data or a deliberate authoring choice requires one-metre coordinates. The project stores both snap.enabled and snap.stepKm.

Data behavior

Visual changes with structural consequences.

Classifications

Shared classifications use layer as Type. Location and area Subtype is stored in kind; path Subtype remains type for schema compatibility. Built-in values receive consistent colors, while Other / custom preserves author-defined values.

Ordered paths

Path order is meaningful. Water paths should run from source to mouth. Cumulative distances are recalculated automatically after geometry edits.

Linked intersections

When a location and path point share a location_id, moving either keeps all linked X/Y coordinates aligned. Each record retains its own elevation.

YAML support

The importer handles mappings, sequences, flow coordinate arrays and maps, comments, quoted scalars, and literal or folded block text. Anchors, aliases, tags, and multi-document streams are intentionally unsupported.

Preservation: Existing fields that the editor does not expose are retained during the project session and re-exported.

Files and export

Working state in; clean sources out.

.iwspatial project

The primary authoring format embeds the reference image, map data, layer visibility, viewport, metric zoom, snapping preference, and selection. Version 3 projects remain portable between computers; earlier editor projects are migrated and their viewport scales are clamped safely.

Spatial Context YAML

Export produces world-geography.yaml and world-spatial.yaml. Background imagery and other editor-only state are never written to those files.

Validation

Run validation before export. It checks the structures and relationships the editor can verify, then reports problems without silently rewriting intent.

Privacy and portability

Your map stays yours.

The Visual Editor has no analytics, API calls, accounts, uploads, or runtime dependencies. Every open, import, save, and export operation happens locally in the browser.
